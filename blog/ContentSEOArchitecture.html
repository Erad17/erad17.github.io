§ The Architecture

FIG 01 — DATA MODEL = BUSINESS MODEL REV A — DRAWN BY Marho Eradiri

The problem. The business provides in-home tutoring across North/Central New Jersey and NYC, with a PO Box address in New York, NY 10028. Despite serving a multi-county, two-state territory, the site has zero location-based landing pages and no structured geo-data anywhere in the markup. A parent searching "tutoring in Montclair NJ" or "SAT prep Westchester" has no path to this site through local SEO — the business is invisible to the queries that would find it.

Current

No location pages. Contact page lists address. No city-level content.

No schema.org geo-data. None of the LocalBusiness / areaServed / geo-coordinate markup Google reads.

No URL structure for geography. No /montclair-nj/ or /westchester-ny/ paths.

Target

A single taxonomy with six terms. Each coverage area is a taxonomy term with structured fields.

Schema.org LocalBusiness on every term page. areaServed, address, service area.

Canonical URLs: /coverage/montclair-nj/, /coverage/westchester-ny/

§ The Taxonomy Model

One taxonomy, six regions, room to grow. The proposal is a coverage_area custom taxonomy registered to the service custom post type. Each term represents a geographic region the business serves. Each term carries structured data via Carbon Fields. A single Twig template renders every term page with schema.org markup.

Carbon Fields on Each Term

// Plugin: dolphin-core/fields/coverage-area-fields.php Container::make('term_meta', 'Coverage Details') ->where('term_taxonomy', '=', 'coverage_area') ->add_fields([ Field::make('text', 'region_name', 'Display Name'), Field::make('textarea', 'counties', 'Counties Served'), Field::make('textarea', 'zip_codes', 'ZIP Code Range'), Field::make('rich_text', 'description', 'Region Description'), Field::make('text', 'travel_note', 'Travel / Availability Note'), Field::make('complex', 'featured_cities', 'Featured Cities') ->add_fields([ Field::make('text', 'city', 'City Name'), Field::make('text', 'school_district', 'School District'), ]), ]);

Rationale. The featured_cities repeater gives each region page a list of specific cities and school districts — Montclair, Hoboken, Scarsdale, Park Slope — without creating individual pages for each. These are editorial data points that add local relevance without multiplying URLs. The description field allows a unique, SEO-rich paragraph per region.

§ Template & Schema

One template renders every region. A single Twig template — taxonomy-coverage_area.twig — receives the term object and its Carbon Fields data. The template renders:

  • Region name, description, counties list — from Carbon Fields
  • Services available in this region — queried from the service CPT associated with the term
  • Featured cities with school districts — from the repeater field
  • Consultation CTA — prominent, region-specific
  • Schema.org LocalBusiness — generated from term data in the PHP controller
// taxonomy-coverage_area.twig — data prepared by PHP controller {% extends "base.twig" %} {% block content %} <article class="coverage-region"> <h1>{{ term.name }}</h1> <p class="region-desc">{{ term.meta('description') }}</p> <div class="region-meta"> <span>{{ term.meta('counties') }}</span> <span>{{ term.meta('zip_codes') }}</span> <span>{{ term.meta('travel_note') }}</span> </div> <section class="region-services"> <h2>Services in {{ term.name }}</h2> {% for service in region_services %} {% include "partials/service-card.twig" with { service: service } %} {% endfor %} </section> {% if term.meta('featured_cities') %} <section class="featured-cities"> <h2>Serving {{ term.name }} families in:</h2> <ul> {% for city in term.meta('featured_cities') %} <li>{{ city.city }} — {{ city.school_district }}</li> {% endfor %} </ul> </section> {% endif %} <div class="cta-band"> <a href="/contact">Request a tutor in {{ term.name }} →</a> </div> </article> {% endblock %}

§ Schema.org Integration

Search engines get structured data, not just text. The PHP controller attached to the taxonomy template generates schema.org markup from the same Carbon Fields data. Each term page carries LocalBusiness markup with areaServed populated from the counties field and address from the business PO Box.

// Generated on /coverage/north-jersey/ { "@context": "https://schema.org", "@type": "LocalBusiness", "name": "Dolphin Academic Prep", "description": "In-home tutoring in North Jersey", "url": "https://www.dolphinacademicprep.com/coverage/north-jersey/", "telephone": "+1-646-490-5075", "address": { "@type": "PostalAddress", "postOfficeBoxNumber": "P.O. Box 1233", "addressLocality": "New York", "addressRegion": "NY", "postalCode": "10028" }, "areaServed": [ { "@type": "State", "name": "New Jersey" }, { "@type": "City", "name": "Montclair" }, { "@type": "City", "name": "Hoboken" } ] }

Google gets exactly the signal it reads for "tutoring in Montclair NJ" — and today the site sends none of it. The proposed architecture sends it on every coverage area page, generated automatically from structured fields, so there is no duplicate content, no manual markup, and nothing to drift out of sync.

§ Why a Taxonomy, Not Pages

The data structure matches the business model. A coverage area is not a page — it is a classification. "Does Dolphin serve Montclair?" is answered by "Montclair is in the North Jersey coverage area," which is a taxonomy lookup rather than a page lookup. That distinction matters:

Approach Assessment Verdict
Individual pages per city Every new city needs a new page, with content duplication and no canonical URL model. 50+ cities = 50+ pages to maintain. Rejected
WordPress multisite per region Massive overhead for an in-home tutoring business. Six WordPress installs, six admin panels, six update cycles. Rejected
coverage_area taxonomy A single taxonomy and template. Add a region = add a term. Add a city = add to the repeater. Schema.org generated from field data. Services queryable by region. Zero duplicate content. Chosen

The taxonomy model also solves the editorial workflow. A staff member opens the Vue admin panel, selects a coverage area, and edits the counties, featured cities, and description — there is no new page to create, no URL to manage, and no SEO plugin to configure. The template handles everything automatically.

SEO Benefit Summary

Each coverage area term page becomes a local landing page with unique content, schema.org markup, a canonical URL, and an XML sitemap entry — all generated from six taxonomy terms where today there is no structured geo-data at all. A parent searching "tutoring in [city]" now has a path to this site through local SEO signals that do not exist today.
