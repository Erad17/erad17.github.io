What's Working

1. Solid SEO Foundation

Yoast SEO is configured with proper meta title, description, canonical URL, Open Graph tags, and structured data (Organization, WebPage, BreadcrumbList, WebSite with SearchAction). The JSON-LD schema markup is comprehensive and well-formed — this is rare on a site of this vintage and a genuine asset.

2. SSL Across the Board

All resource URLs, canonical URLs, and internal links use HTTPS. No mixed-content warnings detected. The MonsterInsights GA4 config includes forceSSL: true.

3. Clear Service Architecture

The navigation hierarchy — Home → Services (with grade-level breakdowns) → Resources → FAQ → Request Info → Contact — is logical and reflects a real understanding of how families shop for tutoring. The content itself is substantive, with detailed exam schedule pages and featured articles.

Critical Issues

1. No Viewport Meta Tag — Site Is Not Mobile-Responsive

The <head> contains no <meta name="viewport"> tag. Mobile browsers render the page at desktop width and zoom out, making text unreadable and navigation unusable on phones. The Twenty Ten theme is a fixed-width (940px) theme from 2010. With roughly 60%+ of tutoring searches happening on mobile, this is costing the business real leads every day. The JD explicitly requires "Desktop, Mobile & Tablet Compatible."

Source: viewport meta tag is absent from the entire <head> block.

2. No Child Theme — Updates Will Destroy Customizations

The site runs on the Twenty Ten parent theme directly. When WordPress updates the theme, any customizations to functions.php, template files, or the footer will be overwritten. The footer currently shows "Proudly powered by WordPress" — a telltale sign that the previous designer either didn't know how to create a child theme or never finished.

Source: #site-generator div contains the anchor: <a href="https://wordpress.org/" class="imprint">Proudly powered by WordPress.</a>

3. Cyclone Slider 2 — Abandoned Plugin

Cyclone Slider 2 (version 3.2.0) loads jQuery Cycle2 and five separate add-on scripts: carousel, swipe, tile, video, plus a Vimeo player. This plugin has not been meaningfully updated in years. It's a performance liability and a security risk. The slider on the homepage is the primary visual element above the fold, and it's powered by abandoned code.

Source: 5 separate Cyclone Slider JS files enqueued in the footer, plus jquery.cycle2.min.js and all its add-ons.

4. No Client Portal Infrastructure

The JD's most ambitious requirement — a secure web portal with login, six e-signable forms, document uploads, and dual notifications — has zero representation in the current source. There is no membership plugin, no form builder capable of e-signatures, and no document management system. This is the single largest gap between the current site and the stated requirements.

Source: no membership plugin, no login form, no e-signature capability detected in enqueued scripts or markup.

5. Fragile Build Pipeline

The site is an awkward hybrid: Elementor is installed and the kit is active (post-19418), but the page content is rendered through Twenty Ten's template hierarchy, not Elementor's canvas. The CSS is a mix of Twenty Ten defaults, Elementor styles, Wonder Blocks utilities, and WP Fastest Cache's combined/minified output. The previous designer appears to have started an Elementor migration and stopped mid-way. This makes the site fragile — any change to one layer risks breaking another.

Source: elementor-kit-19418 is active, but the body uses wp-theme-twentyten template hierarchy.

03 · Recommendations

3. Recommendations & Next Steps

Priority 1 — Critical

Rebuild on a Modern, Responsive Foundation

What: Replace the Twenty Ten theme with a child theme built on a modern, lightweight parent (or a custom lightweight theme) that is fully responsive, accessible, and designed to work with Elementor's template system. Add the viewport meta tag, implement a mobile-first navigation pattern, and ensure all existing content renders correctly across device sizes.

Why: The absence of mobile responsiveness is costing the business leads every day. The Twenty Ten theme is a security and maintenance liability. The half-finished Elementor migration means the site is fragile — any change to one layer risks breaking another.

Approach: The prototype demonstrates a clean-sheet rebuild that preserves the SEO structure, navigation hierarchy, and content while replacing the presentation layer entirely. This approach is faster and more reliable than trying to retrofit responsiveness onto Twenty Ten.

Priority 2 — High Impact

Build the Client Portal

What: Implement the secure family portal as described in the JD — login with email/password, 6 e-signable forms, document uploads with dual notifications, and session scheduling.

Why: This is the JD's most transformative requirement and the feature that differentiates Dolphin Academic Prep from competitors. It's also the feature with zero current implementation — meaning it's the largest scope item and needs to be started early.

Approach: The prototype demonstrates a portal architecture using form workflows, e-signature capture, document vault, and dashboard. In production, this would be backed by WordPress custom post types, ACF field groups, and a forms plugin with e-signature support (or a custom implementation using the WordPress REST API).

Priority 3 — Quick Win

Remove Cyclone Slider 2 and Replace with Native Elementor Slider

What: Deactivate Cyclone Slider 2. Rebuild the homepage slider using Elementor's native slider widget or a lightweight, maintained alternative.

Why: Cyclone Slider 2 is abandoned, loads 5+ unnecessary JS files, and is a security risk. Elementor already includes slider functionality. This is a one-hour fix that eliminates a significant performance and security liability.

Approach: Recreate the four slides in Elementor, map the captions, and configure the fade transition. Deactivate and uninstall Cyclone Slider 2. This removes jQuery Cycle2 and all its add-ons from the page load.

Proposed Approach

A clean-sheet rebuild on a modern WordPress foundation — lightweight custom theme (or well-structured child theme), Elementor for page building, and a custom portal implementation using WordPress custom post types and the REST API. The prototype demonstrates the recommended direction: a design system built on the Navy/Teal/Orange/Gold palette with Fraunces and Public Sans typography, a holiday capsule system, and a fully interactive portal with e-signature workflows.

Key Improvements

1. The Portal Makes the Site a Tool, Not a Brochure

The current site tells visitors what Dolphin does; the prototype lets families do something — sign forms, upload documents, check schedules. This is the difference between a marketing site and a platform. The intake wizard with e-signature capture is the feature that turns the JD's most ambitious requirement from "we'd like this" into "here's how it works."

2. The Holiday Capsule System Turns a Maintenance Burden into a Brand Asset

The JD asks for ~14 holiday-specific looks per year. Manually updating banners for each holiday is a recipe for outdated content. The prototype's calendar-driven system auto-schedules capsules, changes the hero motif, and lets staff preview any capsule with a dropdown — zero manual intervention after setup.

3. The Estimator Bridges the Gap Between "Browse Programs" and "Contact Us"

The current site lists services and asks visitors to call. The prototype's Plan & Pace Estimator lets families drag sliders to see their score gap, weekly pacing, recommended coaching load, and suggested program mix — then sends that estimate directly into a consultation request. This is a conversion tool, not just a content page.
