Editorial Workflow Guide

How staff manage content day to day — from updating a service description to reviewing a signed intake form — without needing a developer.

Interface: Vue 3 admin panel Fallback: Carbon Fields metaboxes Audience: Non-technical staff

Principle

Match the interface to the person managing the content.

The current site's editorial workflow is straightforward: log into WordPress, find the right page in the admin menu, edit a WYSIWYG paragraph, and hope the formatting survives. The "Want more info? Call today: 646-490-5075" sidebar widget — the most consistent call-to-action on the site — appears on nearly every page via a Black Studio TinyMCE widget, requiring staff to navigate to Appearance → Widgets to modify it. The FAQ content lives in the Ultimate FAQ plugin, siloed from the rest of the site. Contact form submissions arrive via VFB Pro with no structured review workflow and no encryption.

The rebuild replaces this with purpose-built editorial surfaces. Each content type gets an interface designed for the person who will use it, rather than the generic WordPress admin that treats every use case the same and serves none of them particularly well. The Vue admin panel is the primary interface, while the Carbon Fields metaboxes are the fallback — staff can choose either.

The shortest version of the difference: A staff member updating a service description goes from "Pages → All Pages → find the right page → edit a WYSIWYG block → hope the phone number widget still looks right" to "Practice Manager → Services → click the service → edit the description field → Save."

The Admin Panel

One dashboard for every content type.

The Vue admin panel is a single-page application loaded inside the WordPress admin. A staff member logs into WordPress, clicks "Practice Manager" in the sidebar, and sees a dashboard with four cards: Services, Coverage Areas, Form Submissions, and Analytics. Each card shows a count and a link. Clicking a card opens the relevant management view — a PrimeVue DataTable with inline editing via a Dialog component. Everything happens in one interface, with no navigation to "Custom Post Types → Services → Edit," no metabox scrolling, and no separate plugin dashboards for forms and analytics.

Dashboard Card What It Shows What Staff Can Do

Workflow 1

Updating a Service

01

Edit a service description

Staff
1
Open the admin panel.

Log into WordPress and click "Practice Manager" in the sidebar. The dashboard loads.

2
Click "Services."

The service catalog opens as a sortable, searchable table. Columns: Service Name, Category, Grade Range, Last Updated.

3
Click the row or the edit icon.

A dialog opens with the service's structured fields: name, category dropdown, grade range, rich-text description, pricing tier. The Content Quality panel on the right shows readability scores and SEO heuristics in real time.

4
Edit and save.

Make your changes and click Save. The dialog closes, the table updates, and the public site reflects the change immediately — no cache flush required (WP Fastest Cache handles this server-side).

01b

Add a new service

Staff
1
Click "+ Add Service" in the Services table header.

A blank dialog opens with the same structured fields.

2
Fill in the fields and save.

The new service appears in the table immediately. It also appears on the public Programs page and any associated Coverage Area pages automatically, with no manual page creation or URL configuration.

Workflow 2

Managing Coverage Areas

02

Update a coverage region

Staff / Owner
1
Click "Coverage Areas" on the dashboard.

A table shows six regions: North Jersey, Central Jersey, NYC — Manhattan, NYC — Brooklyn & Queens, Staten Island, Westchester & Rockland.

2
Click a region to edit.

The dialog shows: region name, counties served (textarea), ZIP code range (textarea), region description (rich text), travel/availability note, and the featured cities repeater.

3
Add a featured city.

Click "+ Add City" in the repeater and type the city name and school district. The city appears in the list on the public region page automatically — there is no new URL or page to manage, because the city is just data now.

4
Save.

The public region page at /coverage/north-jersey/ updates with the new city, refreshed county list, and any description changes. Schema.org LocalBusiness markup regenerates from the updated field data.

Workflow 3

Reviewing Portal Form Submissions

03

Review and countersign an intake form

Admin / Owner
1
Click "Form Submissions" on the dashboard.

A table shows recent submissions: reference number, form type, family name, date submitted, status (submitted / awaiting signature / signed). An unread badge highlights new submissions.

2
Click a submission to open it.

The encrypted data is decrypted server-side and rendered in a read-only review view. All form fields are displayed: student name, grade, subjects requested, goals, parent signature. The signature PNG renders inline.

3
Countersign if needed.

For enrollment agreements or accommodation addenda: click "Countersign" to open a signature pad, and sign with mouse, touch, or stylus. When you click "Submit," the form status changes to "Signed," and both the family and the admin receive email confirmation with a PDF attachment. The audit log records the countersignature with timestamp, IP, and user ID.

4
Mark as processed.

If no countersignature is needed, click "Mark Processed" and the submission moves to the processed queue, where it remains accessible and searchable.

Workflow 4

Writing a Blog Post

04

Publish a new article

Staff
1
Use the standard WordPress post editor.

Blog posts use the native WordPress block editor — the one content type where freeform layout is appropriate. The Custom SEO module (replacing Yoast) adds inline guidance: meta title length, meta description preview, readability score from open-source libraries, and keyword usage suggestions — all rendered in a sidebar panel that matches the Vue admin's design language.

2
Set the category and publish.

Categories match the current site's structure: ARTICLE, HELPFUL HINTS, ANNOUNCEMENTS, BLOG — plus new categories for SAT/ACT Prep, College Admissions, and Learning Resources. The post appears on the public blog, in the XML sitemap, and in any category archive.

3
Schema.org Article markup is automatic.

Title, author, publish date, and featured image are rendered as JSON-LD from post data. No additional plugin configuration required. This is handled by the custom SEO module — the same code that generates LocalBusiness markup for coverage areas and FAQ markup for the FAQ CPT.

Workflow 5

Managing FAQs

05

Add or update a frequently asked question

Staff
1
Click "FAQs" in the admin panel.

A table shows all FAQs organized by category. The current site's FAQ content — including the detailed response about tutoring subjects from Pre-K to Adult — has been migrated into structured fields during the rebuild.

2
Click to edit, or click "+ Add FAQ."

Each FAQ has three fields: question, answer (rich text), and category. The public FAQ page renders them as an accordion with schema.org FAQ markup generated automatically.

3
Save.

The FAQ appears on the public page immediately. Search engines receive structured FAQ data — the same schema.org type the current site generates via Ultimate FAQ, but now generated from our own CPT without a plugin dependency.

Workflow 6

Holiday Capsule Interaction

06

Preview and verify holiday theming

Owner / Marketing
1
Browse the public site.

The capsule system runs automatically — no login required to see it working. A staff member opens the homepage and sees whatever holiday capsule is currently active based on the calendar.

2
Preview an upcoming capsule.

Scroll down to the "Holiday Capsule System" gallery strip on the homepage and click any capsule card (Diwali, Thanksgiving, Winter Break, etc.) to preview it live. Colors, greeting text, and motifs change immediately. The preview is session-only — refreshing the page returns to the calendar's automatic selection.

3
Override if needed.

The dropdown in the header ribbon lets staff manually select a capsule to extend a holiday theme or test a new one. Selecting "Auto" returns to calendar-driven behavior.

These interactions happen on the front end — no wp-admin login required. The people who care about holiday theming (business owner, marketing person) are not necessarily the people comfortable navigating the WordPress admin, so the capsule controls live where those people already are: the public site.

Fallback

What happens if the Vue admin panel is deactivated.

Every content type is backed by Carbon Fields, which provides native WordPress metaboxes. If the dolphin-admin plugin is deactivated — intentionally, accidentally, or during troubleshooting — all content remains editable through the standard WordPress admin. The structured fields appear as metaboxes on the post edit screen. The data is identical, the URLs are unchanged, and the public site is unaffected.

That is not just a nice guarantee on paper. It reflects a design principle: the admin panel is a convenience layer over the data model, not the data model itself. The same principle applies to every custom plugin in the rebuild — portal, SEO, analytics, forms. Each can be deactivated independently without losing data, so the client is never locked in.
