Content Architecture

How the prototype's JavaScript data arrays became a WordPress content model — four CPTs, two theme-option containers, one join key, and a clinical instrument that never touches the database.

CPTs: 4 Theme options: 2 containers Seeded posts: 26

Overview

From data arrays to a content model.

The prototype held its content in JavaScript array literals — SERIES, ESSAYS, SERVICES, RESOURCES, INSURERS, REFLECTION — rendered client-side by builder functions. The SPA→CMS pipeline's Phase 2a classified each array with the same test used across all three projects: editorial content becomes a CPT, configuration becomes theme options, transient data stays out of the CMS. This document records what that test produced here, and where the pipeline had to adapt.

The full pipeline methodology — deterministic parsing, AI section-map inference, CPT registration, Twig component generation, and event bus wiring — is documented in the SPA→CMS Pipeline appendix. This project ran the identical pipeline as Dolphin Academic Prep and the Portfolio build; the outputs below are the project-specific artifacts: section-map.json, css-route-map.json, includes/cpts.php, the Twig component library under views/, and the Phase 3 seeders.

1 · CPT Design

Four post types, one join key.

Every CPT registers with show_in_rest => true and has_archive => false — the SPA page routes (#/essays, #/services, …) become WordPress pages in Phase 3b, and the grids render on those pages. CPT rewrite slugs provide only the single views, which coexist with the pages without rule collisions.

01

imbp_essay — Serial Essays

13 entries

Nine perimenopause installments (days 1–30) and four relationships installments (days 1–12). The body lives in native post_content — the prototype's body[] array maps one element per paragraph, joined on blank lines; the essay template splits it back and applies wpautop() per part. Carbon Fields carry the folio metadata: series (select, stores the series slug), day, read, dek, pull (injected after the third paragraph), margin{label,text}, and domains (a set of sleep / mood / stress / hormones / gut feeding the archive search haystack).

The post slug maps to the SPA hash route. #/essays/the-3-am-wake-up becomes /essays/the-3-am-wake-up/ — the Phase 3a seeder transcribes the prototype slugs verbatim, so every deep link in the prototype resolves to the same essay in the CMS.

02

imbp_series — Essay Series

2 entries

The Perimenopause Series (30 planned, art: dawn) and The Relationships Series (12 planned, art: glacier), both "In progress." Carbon Fields: total (the denominator of the progress bars), art (landscape variant select), standfirst, and status.

The post slug is the join key. Series posts must use the prototype key as their slug — post_name = 'peri' matches ESSAYS[].series = 'peri' — because every essay's series field stores the series slug, and the index cards, archive grouping, and folio progress tracker all join on it. The essay→series select in the admin builds its options from published series posts (get_series_options()), so the join can never silently drift.

// views/pages/essay.twig — the join, in Twig {% set series_key = fn('carbon_get_post_meta', essay.id, 'series') %} {% set series_post = fn('Timber::get_post', { post_type: 'imbp_series', // post_name = the prototype key ('peri' / 'rel') — the join key name: series_key, } ) %}
03

imbp_service — Services

6 entries

The six care offerings, from Initial Psychiatric Evaluation ($250, 60 min) to Children & Adolescent Care (ages 5–18). Carbon Fields: category, duration, price, description, unique_feature, includes{item} (the disclosure bullet list), and the lanes set — insurance / cash / pediatric.

The lanes set drives the Care-Lane Compass. Lane B (cash-pay) lists exactly the services whose lanes include cash — the same filter the prototype's SERVICES.filter(s => s.lanes.includes('cash')) performed client-side, now a Timber::get_posts meta query server-side. The services page's filter chips (All / Insurance / Cash-pay / Children & teens) match on the same field via data-lanes attributes. The pediatric lane carries the age-appropriate filtering: the prototype's minGrade-style age gating (ages 5–18) is expressed through the pediatric lane membership and the service's own copy, exactly as the prototype rendered it.

Cross-component: the intake form consumes every service — the desiredService checkboxes and the #service-choices pre-selection read the native post ID, which the seeder claims from the prototype's numeric ids via import_id parity.

04

imbp_resource — Apothecary Shelf

5 entries

The five downloadable jars — The 3 A.M. Protocol, The Lab Panel Checklist, and three more. Carbon Fields: kind (micro-label), tags (badge set), blurb, meta, and file (an attachment field added for the real asset — the prototype's download button was a stub that toasted "in production this triggers the PDF download").

The fill field stores CSS custom property tokens. Each jar's SVG color is a select whose values are var(--glacier), var(--gold), var(--sage), var(--pine) — kept verbatim so the token wiring resolves against global.css and the jars follow the circadian cascade. The prototype's jarSVG() utility reads the token; the CMS stores it as data, not as a hardcoded hex.

2 · Theme Options Design

Configuration, not content.

Two arrays failed the editorial test and became Carbon Fields theme-options containers — screens a clinician or practice manager edits with intent, not daily content workflow.

Care-Lane Compass

INSURERS + HEADWAY_URL in one container. The prototype's INSURERS is a flat array of nine carrier-name strings — Aetna, BCBS, Carelon, Cigna, Optum, Oscar, Oxford, Regence, SelectHealth — with no per-item metadata, consumed exclusively by mountCompass(). The container keeps add/remove in the editor (a complex field with one name sub-field per row) plus the Headway booking URL that the "Open Headway booking" CTA targets.

mountCompass() is a shared component, mounted twice. The section map's cross-widget dependencies flagged it: the same compass renders at #compass-home on the homepage and #compass-main on the Insurance & Booking page. Phase 2b first built it as a home component, then promoted it to views/components/shared/care-lane-compass.twig when the Insurance page build identified the second mount — both pages now include the shared component with their own wrapper and section-head copy. The render half of mountCompass() moved server-side into Twig; the interaction half (insurer chip status, the not-sure disclosure) stayed client-side as care-lane-compass.js.

// views/pages/home.twig + views/pages/insurance.twig — one component, two mounts {% include "components/shared/care-lane-compass.twig" with { uid: 'cl-home', // or 'cl-main' — unique aria-id prefix mount_id: 'compass-home', // or 'compass-main' (prototype div id) eyebrow: 'The Care-Lane Compass', heading: 'Will my insurance cover this?', insurers: insurers, // theme option rows cash_services: cash_services, // imbp_service where lanes ∋ 'cash' headway_url: headway_url, } %}

Root-Cause Reflection Map

Eight questions, thirty-three answer options, one flattened weight system. The prototype's REFLECTION array nests a weight map inside every option — o.w{sleep,mood,hormones,gut,stress} — which Carbon Fields flattens to w_sleep, w_mood, w_hormones, w_gut, w_stress number sub-fields (0–3; an absent prototype key seeds as explicit 0). Each question also carries a ring assignment (mind / body / gut — the seeded set: body, mind, mind, gut, body, mind, body, mind) and each option an optional lane routing key (new, med, therapy, stuck, functional — consumed by careLane() on the final history question only).

Client-side only — nothing stored or transmitted. The container is localized to window.IntegrstivFinis via wp_localize_script(), and the scoring engine (maxWeights, score, ringLoad, careLane, results) runs entirely in the browser. No answer, no weight total, and no pattern ever reaches a WordPress table, a REST route, or a log. The overlay opens through the event bus — the hero emits reflection:open, the overlay subscribes — so the trigger and the instrument stay decoupled.

Why options and not a CPT. The reflection map is behavioral configuration: clinicians update weights, not daily content editors. A CPT would add an admin archive, public rewrite slugs, and REST exposure for data that must never leave the page. One options screen keeps the whole instrument reviewable at a glance — and out of every public surface. The full decision record is in the Architecture Decision Record, Decision 3.

3 · Pipeline Adaptation

Where the pipeline earned its keep.

The section map correctly identified 42 components across 9 pages (33 page widgets, 6 chrome, 3 overlays), 7 data arrays (six detected plus SERIES, recovered in Phase 2a), and the circadian cross-component dependencies — phaseForHour / applyPhase were routed to global_js and ported into shared.js verbatim, with phase:change on the event bus. But three episodes required the pipeline to adapt rather than merely execute, and each is traceable in the artifacts.

The wrapper-SPA bug, again.

The prototype arrived wrapped in an outer document — an outer <style> containing a single body rule (the iframe-white background), masking the real stylesheet of 485 rules inside the nested document. The Phase 1 parser's style-block selection had already been hardened for this on Dolphin's prototypes — same parser fix, different symptom: there the wrapper masked the script blocks (the parser selects the largest <script>, not the first); here it masked the CSS. The fix held without modification, and the parse completed with all 485 rules extracted and 191 matched to DOM nodes.

The compass_home routing corruption.

The CSS router assigns each rule to a widget bucket by counting how many widget ranges its matched DOM nodes fall into. The compass_home widget's DOM range was too wide — it swallowed 131 site-wide rules that belonged to a dozen other components: the footer colophon, the folio heads, the timeline, the crisis rail, the intake form, the reflection overlay. Left as routed, those rules would have shipped inside one component's scoped CSS file and broken every other component that referenced them.

The Phase 2c agent caught it against the component contracts and reassigned the rules per component: 26 to shared/shared.css, 23 to the intake form, 12 to the footer colophon, and the remaining 70 distributed across nineteen more component files — each reassignment documented in the receiving file's header comment ("css-route-map bucket 'compass_home' — Phase 2c extracts"). The hero bucket had the same failure at smaller scale: its range swallowed the serial essays rail, whose rules were reassigned to home/serial-essays-rail.css per the Phase 2b component contract.

The SERIES miss.

The Phase 1 section map did not detect the SERIES array — a keyed lookup object rather than a rendered list, invisible to both the repeater detector and the data-array scan. The Phase 2a agent found it reading the JS source while mapping field keys, registered imbp_series as a CPT, and recorded the miss in the cpts.php header alongside the other parse-map corrections: JARS is actually RESOURCES, QUESTIONS is actually REFLECTION, ESSAYS uses dek/read/domains rather than the guessed excerpt/readTime/tags. The policy throughout: the source wins, and every discrepancy is written down, not silently normalized.

The pattern across all three episodes. The deterministic phases produce ground truth; the agent phases verify it against the source and the component contracts; every correction is documented in the artifact that carries it. The pipeline did not need new code to handle this prototype — it needed the judgment layers it already had, and a paper trail.
