GA4 Analytics Console

A standalone WordPress plugin — six reporting blocks with KPI scorecards, traffic acquisition engine, content engagement tracker, geographic demographics, conversion funnel, and quota governance. Mock/live dual-mode architecture. Every number traceable to its runReport payload.

Plugin: dolphin-analytics API: GA4 Data API v1 Mode: Mock/Live Dual-Mode
01

Six reporting blocks, one window, every number traceable.

The analytics console is a standalone WordPress plugin rather than a dashboard widget, SaaS embed, or Looker Studio iframe. It connects directly to the GA4 Data API v1, caches responses in WordPress transients, and renders six reporting blocks server-side through Timber. The design philosophy: every number carries a freshness label, every visualization links to the runReport payload that produced it, and color is reserved strictly for state (up, down, stale, throttled) rather than decoration.

2 · Architecture

Mock/live dual-mode with one JSON shape.

The console operates in two modes depending on whether GA4 credentials are configured. The critical architectural decision: the REST endpoint returns the identical JSON shape in both modes, so the JavaScript client has no reason to care whether the numbers came from Google or from a deterministic random number generator.

Live mode: The service account JSON and property ID are stored as WordPress options. The PHP layer instantiates BetaAnalyticsDataClient, builds a RunReportRequest with the requested metrics, dimensions, and date ranges, executes the request, caches the response, and returns source: "live" with a freshness timestamp and token consumption data.

Mock mode: When no credentials are configured — or the API call fails with a 429, 400, or network error — the PHP layer falls back to a deterministic mock engine. This engine mirrors the prototype's JavaScript PRNG (mulberry32, same seed logic), the same static data arrays (KPI_DEFS, CHANNELS, PAGE_PATHS, COUNTRIES, FUNNEL_STEPS), and the same seasonal factor model. The mock engine is bit-exact with the JavaScript version — verified cross-language. The response returns source: "mock" with status: "demo".

Which mode is active is invisible to the client. The REST response shape is identical in both modes. The JS client checks json.source — if it's "live" or "cache", it renders the REST data directly. If it's "mock" or "error_fallback", it falls back to the client-side mock engine (the original prototype's computeKPIs/computeChannels/etc. functions). The Delta Scrubber, Command Palette, and all interactions work identically in both modes, which means the dashboard is always functional — demo-ready without credentials, production-ready with them.

3 · Reporting Blocks

Six reporting blocks, one committed window.

01

Executive KPI Scorecards

Six headline metrics — activeUsers, sessions, screenPageViews, averageSessionDuration, conversions, totalRevenue — rendered as delta cards with period-over-period comparison. Both windows (current 30 days and previous 30 days) live in a single dateRanges array, so the comparison pair is returned by GA4 rather than reconstructed client-side from two separate calls. Each KPI card carries a sparkline (live data in the current range, ghost line for the comparison period), a delta with redundant encoding (triangle shape + plus/minus sign + color — deuteranopia-safe by design), and a source chip showing freshness and provenance.

02

Traffic Acquisition Engine

sessionDefaultChannelGroup broken out against sessions, engagementRate, and conversions. A volume/quality toggle re-ranks channels without a second API call — channels that are big-but-shallow (Paid Social: 4th on volume, 7th on quality) are exposed by the toggle. Each channel row shows a dual bar: session volume (upper) and quality composite (lower). The filter chain is visible in the block header: "Ranked by sessions — re-ranked from the same response, no second API call." The point is to make the API's cost visible instead of hiding it — the dashboard is upfront about what it asked for.

03

Content Engagement Tracker

Top 25 landing pages by landingPagePlusQueryString with screenPageViews, engagementRate, averageSessionDuration, and conversions. Hard limit of 25 with explicit offset-based pagination — "Load next 25" issues a new request rather than letting an infinite scroll fire unbounded queries, so the table can never spike quota by being scrolled. Each row links to its runReport payload so the number is traceable. Client-side search filters the loaded rows without a request, and columns are sortable with aria-sort indicators. The empty state reads: "GA4 returned zero rows for this filter — that is a real answer, not an error."

04

Geographic Demographics

Country-level user distribution with drill-through to city. Rendered as a schematic bin map — not a geographic projection — chosen deliberately so a 13-inch laptop reads density without the small-state invisibility problem of a true choropleth. The ranked sidecar list carries the exact figures. Clicking a row drills to city level; the parent row is pinned and the map animates. A "Schematic bin map, not a geographic projection" disclaimer is displayed prominently, because being upfront about how data is represented is part of the design.

05

Filtered Conversion Funnel

Dolphin-specific events — program_viewed, consultation_requested, intake_submitted, session_booked — rendered as a filtered funnel with strict dimensionFilters. The active notExpression filter chain is visible in the block header ("session_start · first_visit · user_engagement · page_view · scroll · session_end — excluded from the count") so nobody mistakes a filtered number for a total. Each step shows the absolute count, the percentage-of-sessions drop, and the step conversion rate. The funnel bar shows the drop marker from the prior step. This is the reconciliation point — it's the number most likely to be argued about in a meeting, and the payload recorder makes it traceable.

Mock ratios: ~600K sessions → ~180K program views → ~24K consultations → ~8K intakes → ~3K booked sessions. These mock ratios mirror realistic tutoring business conversion rates — not ecommerce events.

06

Quota & Cache Governance

The only block leadership can't turn off. Tracks hourly token consumption against the GA4 quota cap, cache hit ratio, stale-while-revalidate age, per-block freshness, source, and token cost. A per-block freshness ledger shows six blocks with their source (live:BetaAnalyticsDataClient / cache:redis / cache:redis (swr) / live:429 → retry), age in seconds, rows returned, and state chip. The quota gauge in the header bar is a first-class instrument — a circle gauge showing percentage consumed with remaining tokens — and it is reporting, not ops trivia. Stale numbers are labeled stale and throttled numbers are labeled throttled, without exception. The design principle: "We would rather show a real number with a freshness label than a polished number nobody can trace."

4 · Signature Interaction

The Delta Scrubber teaches period-over-period analysis through direct manipulation.

A date-range band rendered on a 365-day sparkline track. The band has two grip handles for resizing and is draggable for repositioning. A comparison band (dashed) follows the current window at a fixed offset. A chain line connects the two windows. A cache coverage strip under the band shows how much of the selected window is served from cache vs. requiring a live API call — the user learns that sub-threshold moves cost nothing because they resolve against Redis.

Keyboard accessibility: Arrow keys shift the window one day. Shift+Arrow resizes by one day. Home/End snap to the full range. Presets (Last 30 vs prev 30, QTD vs prior QTD, BFCM vs same LY, YoY window) provide common comparison windows. Every interaction updates the header window readout and the scrubber foot — showing the current state chip (live/cached/stale/throttled), the preset name, and the cost hint.

The interaction teaches cost. While dragging, the cache coverage updates live. The scrubber foot updates: "cache:redis · age 412s" on a cached window, "committing batchRunReports…" on a live request. The projected token cost for the selected window is shown in the scrubber foot. The cost model becomes something you feel while dragging rather than something you read about — small moves are free and large moves cost tokens, and the scrubber shows you which is which without a trip to the documentation.

5 · Command Palette

⌘K indexes every metric, dimension, property, and action.

The Command Palette (⌘K) indexes every metric (activeUsers, sessions, screenPageViews, averageSessionDuration, conversions, totalRevenue), every dimension (sessionDefaultChannelGroup, landingPagePlusQueryString, eventName, country, city), every property, every payload recording, every preset, and every action (force revalidate, toggle theme, copy deep link). Results are grouped by category (Views, Metrics, Dimensions, Properties, Payloads, Actions) with icons and subtitles. Arrow keys navigate, Enter selects, and Escape dismisses. The palette is the fastest way to jump from any metric to its block.

6 · Design Doctrine

Color is reserved for state.

The console's design philosophy is documented in its own "Design Doctrine" page. The key principles:

  • Color reserved strictly for state. Up (green), down (red), stale (amber), throttled (orange). When everything is highlighted, nothing is — so the paper/teal/navy palette does the everyday work and color carries the signal.
  • Tabular numerals on every figure. Columns that don't align are columns that get misread. Every KPI value, every table cell, every delta uses font-variant-numeric: tabular-nums.
  • Delta encoding that survives deuteranopia. Roughly one in twelve men has a red-green color vision deficiency. Every delta carries three redundant channels: shape (triangle up, triangle down, bar for flat), sign (explicit + or −), and color — plus a text alternative announced to screen readers.
  • Hairline rules instead of card shadows. Shadows imply hierarchy the data doesn't have. Hairline borders group without ranking. The data is dense but legible.
  • Honesty about data quality. Every block displays its source and last-refreshed timestamp. Partial states are surfaced as partial: if three blocks are live and two are degraded, the header says so rather than showing a uniformly confident page.
  • Deep-linkability. Any window and property scope serializes to a URL: ?from=&to=&cmp=&prop=. An executive can paste the exact view they're arguing about into Slack and the recipient lands on the same numbers.

7 · Payload Flight Recorder

Every visualization carries a payload button wired to the recorder.

The payload inspector drawer records every GA4 API request: the full request body, the full response, a diff against the last successful request for the same block, and flight metadata (HTTP status, latency, source, tokens consumed, attempt count, cache status, window, property). The drawer has four tabs: Request (syntax-highlighted JSON), Response (same), Diff vs last (added/removed/changed lines), and Flight Log (metadata grid).

The payload recorder exists because "trust in a number is a function of seeing where it came from," so it ships as a first-class feature rather than a debug tool tucked behind a flag. The recorder view on the dedicated Payloads page lists all four recorded requests as cards with thumbnails, titles, paths, and metadata. Selecting a card loads the full recording in the payload viewer, which can copy the request JSON to clipboard or download it as a .json file.

8 · REST API Design

The PHP layer handles GA4 auth, caching, and quota. The JS never talks to Google directly.

// Plugin: dolphin-analytics — REST endpoint handler public function handle_report($request) { $metrics = explode(',', $request->get_param('metrics')); $dimensions = $request->get_param('dimensions') ? explode(',', $request->get_param('dimensions')) : []; $startDate = $request->get_param('startDate'); $endDate = $request->get_param('endDate'); // Build request fingerprint for caching $fingerprint = md5(json_encode([$metrics, $dimensions, $startDate, $endDate])); // Try cache first $cached = get_transient('dolphin_ga4_' . $fingerprint); if ($cached !== false) { $cached['source'] = 'cache'; return rest_ensure_response($cached); } // Attempt live GA4 call try { $client = $this->get_client(); // BetaAnalyticsDataClient $response = $client->runReport([...]); $data = $this->transform_response($response); $data['source'] = 'live'; $data['lastRefreshed'] = time(); // Cache for configured TTL $ttl = get_option('dolphin_ga4_cache_ttl', 900); set_transient('dolphin_ga4_' . $fingerprint, $data, $ttl); // Track quota consumption $this->track_quota($response); return rest_ensure_response($data); } catch (Exception $e) { // Fallback to mock data return rest_ensure_response($this->mock_report($metrics, $dimensions, $startDate, $endDate)); } }
